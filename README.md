# Luatrix\n\n**Advanced Lua/Luau obfuscator and VM-based code protection.**\n\nLuatrix combines the complete protection pipeline into one branded tool. Every compatible transformation runs automatically, and each generated output receives fresh randomized VM metadata.\n\n## Usage\n\n```text\nluatrix <input> <out>\n```\n\n- `<input>` — source Lua or Luau file\n- `<out>` — obfuscated output file\n\n## Features\n\n- Dynamic code reconstruction\n- Opaque predicates\n- String encoding and runtime decoding\n- String-to-expression conversion\n- Function inlining\n- Randomized variable renaming\n- Virtual-machine protection\n- Per-output randomized virtual opcodes\n- Anti-tamper checks\n- Anti-debug checks\n- Control-flow scrambling\n- Garbage-code insertion\n- Output compression\n- Function wrapping\n- Encoded bytecode payloads\n- LTRIX watermarking\n\n## Randomized virtual opcodes\n\nLuatrix does not rely on a permanent public opcode vocabulary. The virtual instruction mapping is regenerated for every output, so the same semantic operation can receive a different token each time:\n\n```text\nOutput 1: FGH = RET\nOutput 2: LRX = RET\n```\n\nThe generated dispatcher also uses fresh numeric IDs, shuffled instruction tables, and decoy no-op entries. Static signatures based on a fixed `LOAD`, `RET`, or `NOP` label are therefore unreliable across outputs.\n\n## Watermark\n\nEvery generated file is marked with the Luatrix identity:\n\n```text\nLTRIX\n```\n\n## Supported targets\n\n- Lua 5.1–5.4 compatible source\n- Luau source\n- GLua-compatible source\n\nLua-specific VM and bytecode protection is applied only where the target runtime supports it. Other compatible transformations remain available for Luau and GLua inputs.\n\n## Attribution\n\nLuatrix is derived from the upstream Clyde Luau obfuscator and retains the upstream project attribution and license.\n\n## License\n\nThis project is licensed under the [MIT License](./LICENSE).
