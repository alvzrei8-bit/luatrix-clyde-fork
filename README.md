# Luatrix\n\n**Luau obfuscation and VM protection toolkit**  \n**Project watermark: LTRIX**\n\nLuatrix is the rebranded fork of the Clyde Luau obfuscator. It provides a hand-written lexer, parser, AST transformation pipeline, string protection, control-flow scrambling, and two virtual-machine backends for Luau source.\n\n> **Status:** This fork currently builds from the TypeScript implementation inherited from the upstream project. The native single-file C++ amalgamation and the LTRIX output watermark are separate migration work and should not be assumed to be present in this branch until committed.\n\n## Features\n\n- Full Luau lexer and recursive-descent parser\n- Type annotations, generics, string interpolation, compound assignments, and `continue`\n- Scope-aware local, parameter, and loop-variable renaming\n- Global-name preservation for Roblox/Luau environments\n- XOR-style string encoding with runtime decoding\n- Control-flow scrambling with dispatch tables and opaque predicates\n- Stack-based virtual machine compiler and generator\n- Register-based virtual machine compiler and generator\n- Debug, normal, and maximum VM protection levels\n- Encoded constants and polymorphic/shuffled VM dispatch\n- Optional compression, junk-code insertion, and one-line output\n- Syntax validation before transformation\n- CLI tools for lexing, parsing, obfuscation, and VM output\n- Express-based development server\n\n## Opcode randomization\n\nThe VM generator is designed around a per-output instruction mapping rather than a permanent public opcode vocabulary. A generated output can map a semantic operation to one token or numeric ID while a later output maps the same operation differently:\n\n```text\nOutput 1: FGH -> RET\nOutput 2: LRX -> RET\n```\n\nConsumers should treat generated opcode IDs and dispatch-table layout as output-specific. Do not rely on stable opcode names when analyzing or loading an obfuscated result.\n\n## Architecture\n\n`Source -> Lexer -> Parser -> AST passes -> Printer or VM compiler -> Luau output`\n\n### Source transformation passes\n\n| Pass | Purpose |\n| --- | --- |\n| Identifier renaming | Renames locals and parameters while preserving configured globals |\n| String encoding | Replaces string literals with runtime-decoded values |\n| Control-flow scrambling | Converts selected flow into guarded dispatch structures |\n| Printer/compression | Emits compact, optionally one-line Luau |\n\n### VM backends\n\n| Backend | Use |\n| --- | --- |\n| Stack VM | Push/pop instruction execution with a compact instruction set |\n| Register VM | Register-oriented execution with fewer operand-stack operations |\n\nProtection levels are exposed by the VM CLI:\n\n- **Debug** — easiest to inspect while developing integrations\n- **Normal** — encoded constants and shuffled dispatch\n- **Maximum** — strongest available VM generation and compression settings\n\n## Requirements\n\n- Node.js 18 or newer\n- npm\n- TypeScript 5.3 or newer through the project dependencies\n\n## Install and build\n\n```bash\nnpm install\nnpm run build\n```\n\n## CLI usage\n\nObfuscate a source file:\n\n```bash\nnpm run obfuscate -- input.lua -o output.lua\n```\n\nEnable string encoding and control-flow scrambling:\n\n```bash\nnpm run obfuscate -- input.lua --encode-strings --scramble -o output.lua\n```\n\nGenerate VM-protected output:\n\n```bash\nnpm run obfuscate -- input.lua --vm --max --compress -o output.lua\n```\n\nUseful flags include:\n\n| Flag | Effect |\n| --- | --- |\n| `--vm` | Generate VM-protected output |\n| `--max` / `--advanced` / `--production` | Use maximum VM generation level |\n| `--encode-strings` | Enable string encoding |\n| `--scramble` | Enable control-flow scrambling |\n| `--junk` | Enable junk-code generation |\n| `--compress` | Enable output compression |\n| `--one-line` | Emit compact one-line output |\n| `--no-rename` | Disable local renaming |\n| `--no-preserve` | Disable global-name preservation |\n| `-o <file>` | Write output to a file |\n\n##
